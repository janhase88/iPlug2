# Windows VST3 Vulkan/Skia Baseline

## WM message pump and invalidation
- `IGraphicsWin::OnDisplayTimer()` drives redraw eligibility on both timer- and vblank-driven hosts. It drains queued `WM_VBLANK` messages, filters duplicates using `mLastProcessedVBlank`, and skips frames by advancing `mVBlankSkipUntil` when a frame overruns.【F:IGraphics/Platforms/IGraphicsWin.cpp†L123-L281】
- When dirty regions are detected, the handler pixel-aligns them, calls `InvalidateRect()` for each region, and flips `mPaintPending` from `false` to `true`. The first transition notifies the per-instance `InstancePaintBudget`, keeping outstanding paint accounting scoped to the current editor.【F:IGraphics/Platforms/IGraphicsWin.cpp†L235-L276】【F:IGraphics/Platforms/IGraphicsWin.h†L233-L255】
- Edit controls and resize paths force synchronous `UpdateWindow()` calls to keep text entry and live resizing responsive without waiting for the next timer/vblank tick.【F:IGraphics/Platforms/IGraphicsWin.cpp†L255-L269】

## WM_PAINT processing
- Each `WM_PAINT` clears `mPaintPending`, signals the local `InstancePaintBudget` that a drain completed, and clamps the counter to zero if underflow is detected so teardown leaves a consistent per-instance budget.【F:IGraphics/Platforms/IGraphicsWin.cpp†L666-L742】
- The paint handler coalesces the OS invalidation region, aligns rectangles back to logical pixels, and skips drawing when the Vulkan device or swapchain has already been torn down (e.g., during window shutdown).【F:IGraphics/Platforms/IGraphicsWin.cpp†L671-L725】
- `ValidateRect()` is called unconditionally after painting so Windows does not immediately requeue `WM_PAINT`, which would otherwise clog the message queue under heavy load.【F:IGraphics/Platforms/IGraphicsWin.cpp†L733-L738】

## VBlank worker coordination
- VSync-enabled sessions spin a dedicated worker thread via `StartVBlankThread()` and `OnVBlankRun()` to wait on GPU vertical blank, incrementing `mVBlankCount` and queuing `WM_VBLANK` messages.【F:IGraphics/Platforms/IGraphicsWin.cpp†L283-L345】【F:IGraphics/Platforms/IGraphicsWin.cpp†L3006-L3028】
- `VBlankNotify()` coalesces ticks, bails out early if the local `InstancePaintBudget` reports pending paints, and otherwise posts `WM_VBLANK`. Failures fall back to `SendMessageTimeoutW()` with `SMTO_ABORTIFHUNG` to avoid blocking the worker when the UI queue is saturated, while `mPendingSyncVBlank` captures the freshest tick for synchronous delivery.【F:IGraphics/Platforms/IGraphicsWin.cpp†L3043-L3125】
- The worker tracks outstanding posts with `mVBlankMessagePending` to prevent duplicate queueing, promoting the newest counter to a synchronous send when backlog accumulates.【F:IGraphics/Platforms/IGraphicsWin.cpp†L3037-L3090】

## WM_PAINT/WM_VBLANK backlog symptoms
- When an editor's `InstancePaintBudget` reports pending paints the local vblank notifier refuses to enqueue fresh `WM_VBLANK` messages, preventing that instance from piling onto its own backlog while allowing other editors to continue dispatching.【F:IGraphics/Platforms/IGraphicsWin.cpp†L3043-L3070】
- `PostMessageW()` failures on the vblank path treat `ERROR_NOT_ENOUGH_QUOTA` as a saturated queue, caching the newest tick in `mPendingSyncVBlank` before invoking the synchronous `SendMessageTimeoutW()` fallback to replay the most recent frame once the UI thread drains the backlog.【F:IGraphics/Platforms/IGraphicsWin.cpp†L3066-L3116】
- The synchronous retry only waits 16 ms before bailing (`SMTO_NORMAL` + `kSendTimeoutMs`), releasing `mVBlankMessagePending` when no asynchronous post is pending so the worker can retry on the next tick. Repeated timeouts therefore throttle VSYNC delivery while still blocking the worker thread for short bursts whenever the UI queue is saturated.【F:IGraphics/Platforms/IGraphicsWin.cpp†L3046-L3122】
- If even the synchronous fallback cannot reach the UI thread within 16 ms the notifier clears `mVBlankMessagePending`, letting the worker retry next tick but also dropping the frame that triggered the failure—evidence of a saturated queue that is already discarding work.【F:IGraphics/Platforms/IGraphicsWin.cpp†L3046-L3086】
- Timer callbacks that deliver `OnIdle()` share a hidden message window; when its `PostMessageW()` fails under load the callback flag is simply reset, so `OnIdle()` ticks disappear silently while the queue remains clogged.【F:IPlug/IPlugTimer.cpp†L150-L208】

## Host integration and scaling
- The VST3 view class accepts `kPlatformTypeHWND`, opens the editor window, and mirrors host-driven resize requests into `IGraphicsWin::OnParentWindowResize()` only when host resizing is enabled.【F:IPlug/VST3/IPlugVST3_View.h†L41-L130】
- `setContentScaleFactor()` directly updates the editor's screen scale so DPI changes propagate before the next render tick.【F:IPlug/VST3/IPlugVST3_View.h†L140-L145】

## Idle/timer interaction
- `IPlugAPIBase::CreateTimer()` (not shown) provisions a 20 Hz UI timer; `OnTimer()` drains MIDI/parameter queues on the UI thread and always calls `OnIdle()` so DSP/editor synchronization keeps running even if rendering is throttled.【F:IPlug/IPlugAPIBase.cpp†L134-L195】
- `IDLE_TIMER_RATE` fixes the nominal cadence at 20 Hz, but because every timer callback routes through the shared message window a saturated queue stretches the interval or drops ticks entirely, delaying MIDI/parameter propagation alongside `OnIdle()` work.【F:IPlug/IPlugConstants.h†L111-L111】【F:IPlug/IPlugTimer.cpp†L66-L217】
- In VSYNC mode the HWND message pump also drives `OnDisplayTimer()` through posted `WM_VBLANK` messages, while non-VSYNC paths use `WM_TIMER` to ensure `OnDisplayTimer()` still fires when the worker is idle.【F:IGraphics/Platforms/IGraphicsWin.cpp†L283-L347】

## Shared scheduling state inventory
- `nWndClassReg` tracks how many editors have registered the shared window class so repeated `OpenWindow()` calls reuse the class and teardown only happens after the last instance closes. Mismatched increments/decrements would leak registration or unregister while other editors are still live.【F:IGraphics/Platforms/IGraphicsWin.cpp†L46-L47】【F:IGraphics/Platforms/IGraphicsWin.cpp†L1707-L1789】【F:IGraphics/Platforms/IGraphicsWin.cpp†L1948-L1980】
- Each `IGraphicsWin` owns an `InstancePaintBudget` that increments when invalidations schedule work, decrements as drains finish, and exposes `PendingPaints()` for local WM_VBLANK gating—removing the shared `sPendingPaintCount` bottleneck between instances.【F:IGraphics/Platforms/IGraphicsWin.h†L233-L255】【F:IGraphics/Platforms/IGraphicsWin.cpp†L235-L276】【F:IGraphics/Platforms/IGraphicsWin.cpp†L666-L742】【F:IGraphics/Platforms/IGraphicsWin.cpp†L3043-L3125】
- `WM_VBLANK` (custom message ID) and `IPLUG_TIMER_ID` (timer ID 2) are process-wide constants routing frame ticks through the Windows message pump. Collisions with host-defined IDs would break scheduling, so future refactors should isolate them behind per-instance registration or host negotiation.【F:IGraphics/Platforms/IGraphicsWin.cpp†L60-L79】【F:IGraphics/Platforms/IGraphicsWin.cpp†L283-L345】
- Static storage caches (`IGraphicsWin::sPlatformFontCache`, `IGraphicsWin::sHFontCache`) sit alongside scheduling state. While they target font reuse, they share the same global lifetime rules as the paint counter and should be audited if Vulkan/Skia contexts are torn down asynchronously during heavy load.【F:IGraphics/Platforms/IGraphicsWin.cpp†L68-L76】【F:IGraphics/Platforms/IGraphicsWin.h†L232-L241】

## Host integration singletons
- `IPlugAPIBase::CreateTimer()` is called by both the combined component (`IPlugVST3`) and the controller object, so every plugin instance spins at least two UI timers that all enqueue callbacks through the shared timer facility.【F:IPlug/VST3/IPlugVST3.cpp†L29-L108】【F:IPlug/VST3/IPlugVST3_Controller.cpp†L24-L110】【F:IPlug/IPlugAPIBase.cpp†L134-L195】
- The Windows timer backend funnels those callbacks through a single hidden message window and timer queue guarded by static globals (`sMessageWindow`, `sTimerQueue`, `sTimers`). When `PostMessageW()` to that window fails under load the callback flag is just cleared, meaning one saturated queue can drop `OnIdle()` ticks for every instance sharing the singleton.【F:IPlug/IPlugTimer.cpp†L66-L217】
- `IGraphicsWin::OpenWindow()` still relies on the process-wide window class registration counter (`nWndClassReg`) and shared `WndProc`. A stalled teardown keeps the class registered and blocks fresh window creation for other instances, so the refactor needs guardrails around shared HWND lifecycle to prevent serialization at the host boundary.【F:IGraphics/Platforms/IGraphicsWin.cpp†L46-L47】【F:IGraphics/Platforms/IGraphicsWin.cpp†L1707-L1789】【F:IGraphics/Platforms/IGraphicsWin.cpp†L1948-L1980】

## Shared GPU resource caches
- `WinVulkanDeviceCoordinator` centralizes a process-wide `VkInstance`, logical device, and presentation queue inside a static `SharedState`. Each editor request either reuses the cached snapshot or spins up a new device, increments `activeClients`, and tracks generations so teardown only happens once the last consumer releases it.【F:IGraphics/Platforms/WinVulkanDeviceCoordinator.h†L96-L224】
- `IGraphicsWin::CreateVulkanContext()` pulls that shared snapshot into each window, storing only per-editor surfaces, semaphores, and fences. If a host skips `DestroyVulkanContext()` the coordinator never decrements `activeClients`, leaving the global device alive and preventing clean re-initialization for other instances.【F:IGraphics/Platforms/IGraphicsWin.cpp†L1236-L1365】
- `IGraphicsSkia::EnsureSwapchainSurface()` keeps a per-instance cache of wrapped `SkSurface` objects keyed by swapchain image. The cache assumes the shared device and queue remain valid; `ResetVulkanSwapchainCaches()` clears stale surfaces whenever the swapchain rebuilds so recycled Skia resources do not hold onto destroyed Vulkan images.【F:IGraphics/Drawing/IGraphicsSkia.cpp†L210-L282】【F:IGraphics/Drawing/IGraphicsSkia.cpp†L1045-L1086】
